# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Класс реализует интерфейс `IEvents`, который описывает методы брокера (`on`, `emit`, `trigger`). Модели и представления зависят от этого интерфейса, а не от класса `EventEmitter`: в их конструкторы можно передать любой объект с такими методами.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

В приложении используются две сущности, описывающие данные: товар и покупатель.

#### Интерфейс IProduct

```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

Описывает товар. Поля:

- `id` — уникальный идентификатор товара;
- `description` — текстовое описание;
- `image` — путь к изображению;
- `title` — название товара;
- `category` — категория (софт-скил, хард-скил, дополнительное, другое, кнопка);
- `price` — цена в синапсах. Может быть `null`, если товар бесценный.

#### Тип TPayment

```ts
type TPayment = "card" | "cash" | "";
```

Описывает способ оплаты:

- `'card'` — оплата картой;
- `'cash'` — оплата наличными;
- `''` — способ оплаты ещё не выбран.

#### Интерфейс IBuyer

```ts
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

Описывает покупателя. Поля:

- `payment` — способ оплаты;
- `email` — электронная почта покупателя;
- `phone` — телефон покупателя;
- `address` — адрес доставки.

#### Вспомогательные типы

```ts
interface IFormChange {
  field: string;
  value: string;
}

type TOrderFormData = Pick<IBuyer, "payment" | "address">;
type TContactsFormData = Pick<IBuyer, "email" | "phone">;

interface IActions {
  onClick: () => void;
}
```

- `IFormChange` — данные события изменения поля формы (имя поля и новое значение);
- `TOrderFormData` — данные формы первого шага оформления;
- `TContactsFormData` — данные формы второго шага оформления;
- `IActions` — обработчик клика, который презентер передаёт в конструктор карточек и окна успеха.

### Модели данных

Работа с данными в приложении реализуется тремя классами, разделёнными по зонам ответственности: каталог товаров, корзина и покупатель.

#### Класс ProductsData (каталог)

**Назначение:** хранит массив всех товаров, доступных для покупки, и товар, выбранный для подробного отображения.

**Зона ответственности:** предоставление доступа к списку товаров и к выбранному товару.

**Конструктор:** `constructor(events: IEvents)` — принимает брокер событий. Создаёт пустой каталог.

**Поля:**

- `items: IProduct[]` — массив всех товаров;
- `preview: IProduct | null` — товар, выбранный для подробного отображения. `null`, если ничего не выбрано;
- `events: IEvents` — брокер событий.

**Методы:**

- `setItems(items: IProduct[]): void` — сохраняет массив товаров и генерирует событие `products:changed`;
- `getItems(): IProduct[]` — возвращает массив товаров;
- `getItem(id: string): IProduct | undefined` — возвращает один товар по его id;
- `setPreview(item: IProduct): void` — сохраняет товар для подробного отображения и генерирует событие `preview:changed`;
- `getPreview(): IProduct | null` — возвращает товар для подробного отображения.

#### Класс BasketData (корзина)

**Назначение:** хранит массив товаров, выбранных пользователем для покупки.

**Зона ответственности:** управление списком товаров в корзине.

**Конструктор:** `constructor(events: IEvents)` — принимает брокер событий. Создаёт пустую корзину.

**Поля:**

- `items: IProduct[]` — массив товаров в корзине;
- `events: IEvents` — брокер событий.

**Методы:**

- `getItems(): IProduct[]` — возвращает массив товаров в корзине;
- `addItem(item: IProduct): void` — добавляет товар в корзину и генерирует событие `basket:changed`;
- `removeItem(item: IProduct): void` — удаляет товар из корзины и генерирует событие `basket:changed`;
- `clear(): void` — очищает корзину и генерирует событие `basket:changed`;
- `getTotalPrice(): number` — возвращает стоимость всех товаров в корзине;
- `getQuantity(): number` — возвращает количество товаров в корзине;
- `contains(id: string): boolean` — проверяет наличие товара в корзине по его id.

#### Класс BuyerData (покупатель)

**Назначение:** хранит данные покупателя, которые тот указывает при оформлении заказа.

**Зона ответственности:** хранение, валидация и выдача данных покупателя.

**Конструктор:** `constructor(events: IEvents)` — принимает брокер событий. Создаёт объект с пустыми полями.

**Поля:**

- `payment: TPayment` — вид оплаты (`'card'`, `'cash'` или `''`);
- `email: string` — электронная почта;
- `phone: string` — телефон;
- `address: string` — адрес доставки;
- `events: IEvents` — брокер событий.

**Методы:**

- `setData(data: Partial<IBuyer>): void` — сохраняет переданные поля, не затирая остальные, и генерирует событие `buyer:changed`;
- `getData(): IBuyer` — возвращает все данные покупателя;
- `clear(): void` — очищает все поля и генерирует событие `buyer:changed`;
- `validate(): Partial<Record<keyof IBuyer, string>>` — возвращает объект с ошибками валидации. Поле валидно, если оно не пустое. Если поле валидно — его нет в объекте.

События моделей передаются без данных: актуальное состояние презентер получает методами моделей (`getData()`, `validate()` и другими).

### Слой коммуникации

Слой коммуникации отвечает за взаимодействие приложения с сервером. Он получает данные с сервера и отправляет их на сервер, используя базовый класс `Api` из стартового набора.

#### Класс WebLarekApi

**Назначение:** обеспечивает взаимодействие приложения с API сервера «Web-Larёk» — получение списка товаров и отправку заказа.

**Зона ответственности:** выполнение запросов к серверу через переданный в конструктор объект, соответствующий интерфейсу `IApi`. Класс использует **композицию** — он не наследуется от `Api`, а принимает его экземпляр в конструктор.

**Конструктор:**

`constructor(api: IApi)` — принимает объект, соответствующий интерфейсу `IApi`. Обычно это экземпляр класса `Api` из стартового набора.

**Поля:**

- `api: IApi` — объект для выполнения запросов к серверу. Содержит методы `get` и `post`.

**Методы:**

- `getProducts(): Promise<IProductListResponse>` — выполняет GET-запрос на эндпоинт `/product/` и возвращает промис с объектом, содержащим массив товаров (`total`, `items`);
- `postOrder(data: IOrderRequest): Promise<IOrderResponse>` — выполняет POST-запрос на эндпоинт `/order/` и передаёт в него данные заказа (вид оплаты, email, телефон, адрес, сумму и массив id товаров). Возвращает промис с объектом, подтверждающим покупку (`id`, `total`).

### Слой представления (View)

Слой представления отвечает за отображение данных на странице и сбор пользовательских действий. Классы этого слоя наследуются от базового класса `Component`. Представления не хранят данные и не принимают решений: они показывают то, что получили в `render()`, и сообщают о действиях пользователя через события или переданные обработчики.

#### Класс Header (Шапка)

**Назначение:** отображает шапку сайта с логотипом и кнопкой корзины.

**Конструктор:** `constructor(container: HTMLElement, events: IEvents)`

**Поля:**

- `basketButton: HTMLButtonElement` — кнопка корзины;
- `counterElement: HTMLElement` — счётчик товаров;
- `events: IEvents` — брокер событий.

**Методы:**

- `set counter(value: number): void` — выводит количество товаров в корзине.

**События:** при клике на иконку корзины генерирует `basket:open`.

#### Класс Gallery (Каталог)

**Назначение:** контейнер для отображения списка карточек товаров на главной странице.

**Конструктор:** `constructor(container: HTMLElement)`

**Поля:**

- `catalogElement: HTMLElement` — контейнер для карточек.

**Методы:**

- `set catalog(items: HTMLElement[]): void` — принимает массив HTML-элементов карточек и выводит их в галерею.

#### Класс Modal (Модальное окно)

**Назначение:** универсальный контейнер для отображения модальных окон. Не имеет дочерних классов.

**Конструктор:** `constructor(container: HTMLElement)`

**Поля:**

- `closeButton: HTMLButtonElement` — кнопка закрытия;
- `contentContainer: HTMLElement` — контейнер для содержимого окна.

**Методы:**

- `set content(value: HTMLElement): void` — принимает любой HTML-элемент (компонент) и вставляет его внутрь окна;
- `open(): void` — открывает окно;
- `close(): void` — закрывает окно (по клику на крестик, по клику вне окна или при вызове из презентера).

Событий не генерирует.

#### Класс Basket (Корзина)

**Назначение:** отображает список товаров в корзине и общую стоимость.

**Конструктор:** `constructor(container: HTMLElement, events: IEvents)`

**Поля:**

- `listElement: HTMLElement` — список товаров;
- `totalElement: HTMLElement` — общая стоимость;
- `orderButton: HTMLButtonElement` — кнопка «Оформить»;
- `events: IEvents` — брокер событий.

**Методы:**

- `set items(items: HTMLElement[]): void` — выводит карточки товаров в список (при пустом массиве надпись «Корзина пуста» показывается стилями);
- `set total(value: number): void` — выводит общую стоимость;
- `set canOrder(value: boolean): void` — включает или блокирует кнопку «Оформить». Значение определяет презентер.

**События:** при клике на кнопку «Оформить» генерирует `order:open`.

#### Базовый класс Card (Карточка)

**Назначение:** абстрактный базовый класс для всех карточек. Содержит только общее: название и цену.

**Конструктор:** `constructor(container: HTMLElement)`

**Поля:**

- `titleElement: HTMLElement` — название товара;
- `priceElement: HTMLElement` — цена товара.

**Методы:**

- `set title(value: string): void` — выводит название;
- `set price(value: number | null): void` — выводит цену. Для `null` выводится «Бесценно».

#### Абстрактный класс CardWithImage (Карточка с картинкой)

**Назначение:** наследник `Card`, добавляет категорию и изображение. Общий родитель для `CardCatalog` и `CardPreview`, у карточки корзины этих элементов нет.

**Конструктор:** `constructor(container: HTMLElement)`

**Поля:**

- `categoryElement: HTMLElement` — категория;
- `imageElement: HTMLImageElement` — изображение.

**Методы:**

- `set category(value: string): void` — выводит категорию и ставит ей модификатор из `categoryMap`;
- `set image(value: string): void` — устанавливает адрес изображения.

#### Класс CardCatalog (карточка в каталоге)

**Назначение:** карточка товара в каталоге. Наследует `CardWithImage`.

**Конструктор:** `constructor(container: HTMLElement, actions: IActions)` — обработчик клика по карточке передаётся в `actions.onClick`.

**Поля и методы:** собственных нет, всё унаследовано.

#### Класс CardPreview (подробная карточка)

**Назначение:** подробная карточка товара в модальном окне. Наследует `CardWithImage`.

**Конструктор:** `constructor(container: HTMLElement, events: IEvents)`

**Поля:**

- `descriptionElement: HTMLElement` — описание товара;
- `buttonElement: HTMLButtonElement` — кнопка действия;
- `events: IEvents` — брокер событий.

**Методы:**

- `set description(value: string): void` — выводит описание;
- `set buttonText(value: string): void` — текст кнопки («Купить», «Удалить из корзины» или «Недоступно»);
- `set buttonDisabled(value: boolean): void` — состояние кнопки.

Текст и состояние кнопки определяет презентер.

**События:** при клике на кнопку генерирует `card:button` (без данных).

#### Класс CardBasket (карточка в корзине)

**Назначение:** карточка товара в списке корзины. Наследует `Card`.

**Конструктор:** `constructor(container: HTMLElement, actions: IActions)` — обработчик клика по кнопке удаления передаётся в `actions.onClick`.

**Поля:**

- `indexElement: HTMLElement` — порядковый номер товара;
- `deleteButton: HTMLButtonElement` — кнопка удаления.

**Методы:**

- `set index(value: number): void` — выводит порядковый номер.

#### Абстрактный класс Form (Форма)

**Назначение:** базовый класс для форм. Содержит общее управление кнопкой отправки и выводом ошибок.

**Конструктор:** `constructor(container: HTMLElement, events: IEvents, submitEvent: string)` — третий параметр задаёт имя события, которое форма генерирует при отправке.

**Поля:**

- `submitButton: HTMLButtonElement` — кнопка отправки;
- `errorsElement: HTMLElement` — контейнер для ошибок;
- `events: IEvents` — брокер событий.

**Методы:**

- `set valid(value: boolean): void` — включает или блокирует кнопку отправки;
- `set errors(value: string): void` — выводит текст ошибок.

#### Класс OrderForm (форма первого шага)

**Назначение:** выбор способа оплаты и ввод адреса. Наследует `Form<TOrderFormData>`.

**Конструктор:** `constructor(container: HTMLElement, events: IEvents)`

**Поля:**

- `cardButton: HTMLButtonElement` — кнопка «Онлайн»;
- `cashButton: HTMLButtonElement` — кнопка «При получении»;
- `addressInput: HTMLInputElement` — поле адреса.

**Методы:**

- `set payment(value: TPayment): void` — подсвечивает выбранный способ оплаты;

### Слой Презентера (Presenter)

Презентер является связующим звеном между Моделями, Представлением и Слоем коммуникации. Он не содержит разметки и не хранит данные, а лишь реагирует на события, вызывая методы моделей и передавая данные в компоненты View.

**Основные задачи Презентера:**

1. Инициализация всех компонентов View и Моделей. Статичные компоненты (корзина, подробная карточка, обе формы, окно успеха) создаются один раз при запуске, карточки каталога и корзины создаются динамически.
2. Подписка на события от View и Моделей (например, `card:select`, `basket:open`, `order:submit`, `basket:changed`).
3. Обработка этих событий: получение данных из моделей, валидация, подготовка данных для View и вызов `render()`. Представления перерисовываются при событиях моделей, а при открытии окон разметка только передаётся в модальное окно.
4. Отправка данных на сервер через `WebLarekApi`. После успешного ответа очищаются корзина и данные покупателя и показывается окно успеха; при ошибке запроса она выводится в консоль.

В данном проекте Презентер реализован в основном скрипте src/main.ts для упрощения структуры и соблюдения требований задания. Вся логика связывания Моделей и Представлений находится в обработчиках событий.

### События приложения

В приложении используется событийно-ориентированный подход. Ниже перечислены все события, которые генерируются в моделях и представлениях.

**События Моделей данных** (передаются без данных, актуальное состояние презентер получает методами моделей):

- `products:changed` — каталог товаров загружен или изменён.
- `preview:changed` — выбран товар для подробного отображения.
- `basket:changed` — содержимое корзины изменилось (товар добавлен, удалён или корзина очищена).
- `buyer:changed` — данные покупателя изменились.

**События Представлений (View):**

- `basket:open` — пользователь нажал на иконку корзины в шапке.
- `card:select` — пользователь кликнул на карточку товара в каталоге (передаётся товар; генерируется в обработчике `onClick`, который презентер передаёт карточке).
- `card:button` — пользователь нажал на кнопку в подробной карточке товара («Купить» или «Удалить из корзины»).
- `card:delete` — пользователь нажал на кнопку удаления товара в корзине (передаётся товар; генерируется в обработчике `onClick`, который презентер передаёт карточке).
- `order:open` — пользователь нажал кнопку «Оформить» в корзине.
- `order.payment:change` — пользователь выбрал способ оплаты (данные `IFormChange`).
- `order.address:change` — пользователь ввёл адрес доставки (данные `IFormChange`).
- `contacts.email:change` — пользователь ввёл email (данные `IFormChange`).
- `contacts.phone:change` — пользователь ввёл телефон (данные `IFormChange`).
- `order:submit` — пользователь отправил форму первого шага («Далее»).
- `contacts:submit` — пользователь отправил форму второго шага («Оплатить»).
